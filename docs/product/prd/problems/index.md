# problems

* [PROBLEM-01: Keyword search returns too many matches to judge by hand](PROBLEM-01.md) - A keyword search returns hundreds of matches, and the agent or person must read and judge each one; agents feel this most.
* [PROBLEM-02: The flood costs tokens and time](PROBLEM-02.md) - People who build agents pay for each wasted token; people who use agents wait while the agent reads search output.
* [PROBLEM-03: Current alternatives waste tokens or need setup](PROBLEM-03.md) - Agents cope today with raw keyword search, a sub-agent that reads the files, or vector search, and each one has a cost.
* [PROBLEM-04: Why now: cheap scoring models and CLI-first agents](PROBLEM-04.md) - Cheap yes/no scoring models, agents that call shell tools, first evidence, and a TypeSafe showcase make now the right time.
* [PROBLEM-05: Opportunity: a niche developer tool](PROBLEM-05.md) - jag targets a small group of people who build agents; success means real use and good quality, not reach.
